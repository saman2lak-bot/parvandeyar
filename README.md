# پرونده‌یار

داشبورد فارسی و RTL برای مدیریت پرونده‌های بیمه و پیگیری سریع نواقص.

## اجرا
```bash
npm install
npm run dev
```

## اتصال Supabase
1. در ریشه پروژه فایل `.env` بسازید:
```env
VITE_SUPABASE_URL=your-project-url
VITE_SUPABASE_ANON_KEY=your-publishable-or-anon-key
```
2. فایل‌های `supabase/migrations/001_initial_schema.sql`، سپس `002_roles_and_logic.sql`، `003_deficiency_write_policies.sql` و در پایان `004_security_hardening.sql` را به‌ترتیب در SQL Editor پروژه Supabase اجرا کنید.
3. احراز هویت Email/Password را در Supabase فعال کنید. Migration چهارم برای کاربران موجود پروفایل می‌سازد و برای کاربران جدید نیز پروفایل خودکار ایجاد می‌کند. برای استفاده از ویرایش/حذف پرونده، حذف نقص و مدیریت کارشناسان، نقش کاربر باید `admin` باشد.

در حالت بدون متغیرهای Supabase، برنامه در «حالت نمایشی» اجرا می‌شود: داده‌های نمونه نمایش داده می‌شوند و تغییرات فقط در حافظه ذخیره می‌شوند. با تنظیم متغیرها، داشبورد، فهرست پرونده‌ها، کارشناسان و سوابق فعالیت از Supabase خوانده می‌شوند و تغییر نواقص و ثبت پرونده در پایگاه داده ذخیره می‌شود. کلید Service Role نباید در فرانت‌اند قرار گیرد.

## مسیرها
| مسیر | توضیح |
| --- | --- |
| `/` | داشبورد و آمار کلی |
| `/cases` | فهرست کامل پرونده‌ها با جست‌وجو و فیلتر وضعیت |
| `/experts` | کارشناسان و تعداد پرونده‌های هرکدام |
| `/activity` | سوابق فعالیت ثبت‌شده در `activity_logs` |
| `/settings` | وضعیت اتصال، حساب کاربری و خروج |
| `/login` | ورود با ایمیل و رمز عبور Supabase |

## امکانات
- مدیریت کامل نواقص از Drawer: افزودن، رفع، بازگشایی و حذف با به‌روزرسانی خوش‌بینانه و بازگردانی خودکار در صورت خطا
- ثبت پرونده با اعتبارسنجی Zod و پشتیبانی از ارقام فارسی
- ویرایش اطلاعات پرونده و حذف نرم با ثبت رویداد در `activity_logs`
- محافظت از مسیرها با `RequireAuth` و نشست Supabase
- طراحی واکنش‌گرا با منوی موبایل، حالت تاریک و Lazy Loading صفحات
- تفکیک Chunkها (React، Supabase، فرم‌ها) برای بارگذاری سریع‌تر

## ساختار داده
- `cases`: پرونده‌ها با شماره یکتا در هر سال و حذف نرم
- `case_deficiencies`: نواقص و وضعیت رفع آن‌ها
- `experts`: کارشناسان
- `activity_logs`: سوابق فعالیت
- `profiles`: نقش کاربر (`admin`/`user`) و سیاست‌های RLS

پس از اجرای هر سه Migration، با اجرای `npm run build` نسخه Production در پوشه `dist` ساخته می‌شود. در حالت Supabase، عملیات نوشتن نیازمند نشست معتبر و سیاست‌های RLS مناسب است؛ حالت Demo بدون پایگاه داده و فقط با داده‌های داخل حافظه کار می‌کند.
